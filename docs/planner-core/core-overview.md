# Core Overview

## 這個模組在做什麼

`core.ts` 的任務是：

- 輸入一個 `TrackGraph`
- 輸入目前手上的資源與目標貓咪
- 在所有可能的抽卡行動中搜尋
- 找出「命中目標」且「等價成本最低」的抽卡方案

換句話說，它不是單純模擬一次抽卡，而是在做「最佳路徑搜尋」。

## 可以先抓住的四個觀念

### 1. 圖不是重點，狀態才是重點

雖然底層資料叫 `TrackGraph`，但 planner 真正搜尋的不是單一節點位置，而是整個狀態：

- 目前 cursor 在哪裡
- 上一隻抽到的貓是誰
- 剩餘多少資源
- 已經命中了哪些目標貓

所以可以把它想成：

「在同一個圖上，用不同資源與命中情況，走出不同的未來。」

### 2. 成本不是只有一種，但排序主軸是 `equiv_cost`

`Cost` 是一個 tuple：

```ts
type Cost = [equiv_cost, food_used, ticket_used, platinum_used, legend_used];
```

其中目前真正拿來比較大小的是 `equiv_cost`。

也就是說：

- 系統會保留各種資源的實際使用量
- 但搜尋排序時先看「換算後的總成本」

## 3. target 命中情況用 bitmask 表示

如果目標貓有多隻，planner 不會用陣列或 `Set` 來記錄「哪些已經中了」，而是用一個整數的 bitmask。

這樣的好處：

- 狀態可以更容易比較
- 可以快速判斷是否已經全收集
- 可以有效用於 pruning

## 4. 這是一個加了最佳化技巧的最短路徑問題

從 README 和程式結構來看，這支程式採用：

- Dijkstra
- 或 A*

並搭配：

- dominance pruning
- expansion 上限

所以學習時可以把它分成兩層：

- 業務規則層：單抽、十連、換軌、保底怎麼模擬
- 搜尋策略層：狀態怎麼展開、怎麼比較、怎麼剪枝

## 一句話版本

`core.ts` 是一個把「轉蛋規則」包進「圖搜尋」裡的最佳化規劃器。
